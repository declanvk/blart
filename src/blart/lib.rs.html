30//! Adaptive radix trie implementation
31//!
32//! # References
33//!
34//!  - Leis, V., Kemper, A., & Neumann, T. (2013, April). The adaptive radix tree: ARTful indexing
35//!    for main-memory databases. In 2013 IEEE 29th International Conference on Data Engineering
36//!    (ICDE) (pp. 38-49). IEEE. [Link to PDF][ART paper]
37//!
38//! [ART paper]: http://web.archive.org/web/20240508000744/https://db.in.tum.de/~leis/papers/ART.pdf
39//!
40//! # Crate Features
41//!
42//!  - **nightly** - Enables internal and public use of nightly APIs in the crate. The most
43//!    important features enabled is use of the [`std::simd`] module and the nightly allocator API.
44//!  - **allocator-api2** - This feature is an alternative to the *ni*ghtly* fe*ature which allows
45//!    customizing the allocators.
46//!  - **std** - When enabled, this will cause the crate to use the standard library.
47//!  - **testing** - This feature exposes the `testing` module, which contains helper function for
48//!    writing tests.
49//!  - **_internal** - This feature makes the `raw` module public. The `raw` module contains a lot
50//!    of the implementation details of the radix trie. The items within this module do not carry
51//!    the same guarantees around SemVer that the rest of the crate does. Additionally, there may be
52//!    items in the module which have trie invariants which can cause unsoundness in safe code. This
53//!    module is mostly used for experimentation and likely will be entirely private in the future.
54//!
55//! [`std::simd`]: https://doc.rust-lang.org/stable/std/simd/index.html
