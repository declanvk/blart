pub unsafe fn split_off_unchecked<K: AsBytes, V, A: Allocator, const PREFIX_LEN: usize>(
    root: OpaqueNodePtr<K, V, PREFIX_LEN>,
    key_bytes: &[u8],
    alloc: &A,
) -> SplitOffResult<K, V, PREFIX_LEN>
Expand description

Split the tree rooted by root into two at the given key_bytes.

The keys less than key_bytes end up in one tree, and the keys greater than or equal to key_bytes end up in the other.

The split happens in three phases:

  1. Search for key_bytes from the root, recording every inner node on the path and which of its children are to the left and right of the path (see collect_split_point_nodes). The search stops at one of the following:
    • a leaf, which goes to the left if its key is less than key_bytes and to the right otherwise.
    • an inner node whose prefix does not match key_bytes. The whole node goes to the left or right depending on how its prefix compares to key_bytes.
    • an inner node with no child for the next key byte, which is split at that key byte.
  2. Cut the leaf linked list between the maximum leaf on the left and the minimum leaf on the right. If one side is empty, return the tree unchanged instead.
  3. Walk back up the path, splitting each inner node into a left and right node (see split_ancestor).

Leaf nodes are never split, each one is moved whole to one of the two trees. When an inner node is split, its allocation is reused for one side if the number of children on that side fits the node type, otherwise a new node of the right size is allocated. If a side has only one child, that level of the tree is collapsed into the child, by prepending the inner node’s prefix and key byte to the child’s prefix. Inner nodes that are not reused are deallocated.

§Safety

  • root must be the root of a well-formed tree, and every node of the tree must have been allocated with alloc.
  • This function requires exclusive access to the tree, no other operation may read or write any node of the tree for the duration of this function.
  • After this function returns, root must not be used except through the root pointers in the returned SplitOffResult. For a SplitOffResult::NormalSplit, some of the inner nodes on the path to the split point have been modified or deallocated.

§Panics

This function calls AsBytes::as_bytes on keys in the tree, which may panic. Those calls all happen before the tree is modified, so a panic leaves the tree unchanged.
