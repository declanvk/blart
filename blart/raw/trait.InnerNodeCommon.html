Expand description

This trait contains all the functions/types that every inner node must implement.

This doesn’t necessarily mean that the specific type will be used as an inner node, since that requires assigning it a NodeType and determining its “grow”/“shrink” order. See InnerNode for those details.

§Safety

All structures that implement this trait must be repr(C) and have a Header as the first field of the struct.

Required Methods§

Source

unsafe fn from_header(header: Header<PREFIX_LEN>) -> Self

Create a new inner node with no children, using the prefix from header.

The child count stored in the given header must be reset to zero by the implementation, since the returned node has no children and not resetting can cause UB.

Prefer from_two_children, which upholds the contract below.

§Safety

The new inner node has zero children, which violates assumptions that other inner node operations make that every inner node has at least two distinct children. Until two distinct children are inserted into the inner node, callers may only:

  • write children to the node (write_child or a type-specific write_child_unchecked),
  • read header from the node
  • move, allocate, or store a pointer to the node

Calling any other method on the node before it has two distinct children is undefined behavior.

fn min(&self) -> ChildEdge<K, V, PREFIX_LEN>

Returns the minimum child pointer from this node and it’s key

Since this is a InnerNode we assume that the we have at least one child, (more strictly we have 2, because with one child the node would have collapsed) so in this way we can avoid the Option. This is safe because if we had no children this current node should have been deleted.

fn max(&self) -> ChildEdge<K, V, PREFIX_LEN>

Returns the maximum child pointer from this node and it’s key

Since this is a InnerNode we assume that the we have at least one child, (more strictly we have 2, because with one child the node would have collapsed) so in this way we can avoid the Option. This is safe because if we had, no children this current node should have been deleted.

unsafe fn match_full_prefix( &self, key: &[u8], current_depth: usize, ) -> Result<PrefixMatch, ExplicitMismatch<K, V, PREFIX_LEN>>
where K: AsBytes,

Compares the compressed path of a node with the key and returns the number of equal bytes.

This function will read the full prefix for this inner node, even if it needs to search a descendant leaf node to find implicit bytes.

§Safety

current_depth must be less than or equal to key.len()

§Errors

This function returns an error if there is a mismatch between the provided key and the full prefix.

fn any_child_prefer_leaf(&self) -> OpaqueNodePtr<K, V, PREFIX_LEN>

Returns any child pointer from this node, preferring children that are pointers to leaf nodes.

This function is useful in context where we need to quickly find a leaf of a subtree, but don’t care how we get there.

Source

fn nearest_sibling(&self, child_key_byte: u8) -> Sibling<K, V, PREFIX_LEN>

Return the nearest sibling to the given child key byte.

The given key byte doesn’t need to exist as a child in this inner node.

§Panics

Panics if this node has no child other than the one at child_key_byte.
